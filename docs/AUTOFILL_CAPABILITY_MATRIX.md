# iOS 自动填充能力矩阵（#39）

本文记录 Monica 在 iOS 公开 API 边界内能做什么、不能做什么。iOS 侧不实现 Android 的
无障碍/输入框监听式「任意字段自动填充」，也不承诺系统在所有输入框显示 Monica 建议。

真源：`SwiftPackages/MonicaCore/Sources/MonicaCore/AutoFillCapability.swift`。
界面文案：`App/MonicaApp/AppAutoFillCapabilitySection.swift`。

| 能力 | 可用性 | 说明 |
| --- | --- | --- |
| 系统自动填充扩展（ASCredentialProviderViewController） | 支持 | 系统在识别的用户名 / 密码输入框里向用户展示 Monica 条目；选择后由扩展在用户解锁后填入。 |
| 系统键盘强密码建议 | 由 iOS 决定 | 强密码建议是系统键盘的界面，第三方扩展不能把自己的建议注入其中；可在 Monica 内生成后复制或保存。 |
| 任意输入框监听 / 读取 | 不支持 | iOS 不允许第三方自动填充扩展读取其它 App 或网页的输入框，也不提供跨 App 的无障碍服务。 |
| 内联建议面板 / 自定义键盘注入 | 不支持 | 扩展只响应系统发起的自动填充请求，不能在其他 App 的输入框旁注入面板。 |
| 读取系统默认密码管理器 | 不支持 | App 拿不到「当前默认密码管理器是谁」，只能描述系统设置路径。 |
| 选择系统默认密码管理器 | 由 iOS 决定 | 只能由用户在「设置 › 密码 › 密码选项 › 自动填充密码」里选择，Monica 不能替用户打开或修改。 |
| 打开 Monica 自己的系统设置页 | 支持 | 通过 `UIApplication.openSettingsURLString`。 |
| 直达系统「密码选项」 | 不支持 | 没有公开 URL；只能打开本 App 设置页，再让用户手动进入。 |
| App 内生成密码 / 短语 / PIN / API Token | 支持 | `GeneratorRootView`，结果可编辑、复制，或保存为登录项。 |
| 生成结果保存为登录项 | 支持 | 写入本地加密保险库，并刷新自动填充索引，供系统扩展发布身份。 |

## 系统 QuickType 结果由 iOS 决定

键盘上方的 QuickType 是否出现、出现哪一条、覆盖哪些字段，全部由 iOS 判断。
Monica 无法强制它在所有输入框出现，也不会因为扩展已安装就保证系统展示建议。
系统未识别为用户名 / 密码的输入框不会显示 Monica 建议；此时界面只说明限制，不提示「已可填充」。

## 验收路径

1. 打开密码页 → 生成器 → 生成一个密码，直接编辑结果。
2. 点「保存为登录项」，填写标题（如 `Example`）与网址，保存。
3. 回到保险库，打开该登录项，可复制密码；解锁状态下身份会发布给系统。
4. 在 Safari 的真实用户名 / 密码表单里点输入框，系统 QuickType 应列出 Monica（需先在系统设置启用来源）。
5. 在系统不认识的普通文本框里确认不会出现承诺任意字段可填写的误导文案。

## 已知缺口

- 系统不提供「默认密码管理器」读取/设置 API，设置页只能展示路径与诊断。
- 未在真机跑完整 AutoFill 流程时，模拟器往往读不到凭证身份库，诊断会显示读取失败。
